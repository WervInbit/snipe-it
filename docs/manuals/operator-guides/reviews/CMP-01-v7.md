## Reader And Reasoning

Intended role: Senior Refurbisher. Starting context: Verified open asset and the same physical tracked component.
Outcome: The physical component is installed and its existing tracked identity is linked to the intended asset.

Required alignment: Current component controls and real Extra/Tracked outcome replace the older assumption of automatic baseline substitution.

Chosen reader improvement: Check physical identity before Install and the resulting specification before completion.

Preserved support: Four actions, existing-record reuse, tray/source recognition and tag/serial result verification.

Placement/preservation tradeoff: No catalogue calculation lesson or new registration handoff simply because a search is unresolved; Supervisor resolves that uncertainty.

## Actions And Choices

- Open Components and Add / Install Component.
- Select the same existing tray/storage identity.
- Place physically, then Install once.
- Verify Tracked, tag, serial, link and the displayed asset specification.

## Concrete Changes

- Bestaande identiteit blijft leidend; het resultaat toont dezelfde tag en hetzelfde serienummer.
- Extra en de specificatie worden gecontroleerd; plaatsing vervangt niet vanzelf de Assumed-rij.
- Alleen de kleine componenttab krijgt focus, niet de hele selectie of uitkomst.
- Bij vervanging wordt voor Install/Create gecontroleerd dat het oude onderdeel al is losgekoppeld; onduidelijkheid gaat naar Supervisor.

## Evidence, Checks And Limits

The mounted application is the separate refurbisher-followups checkout,
not the root checkout. Source fingerprints, actual actors, Dutch locale,
owned synthetic fixtures and save/trial boundaries are recorded in the batch
provenance. Genuine English strings and narrow native status-choice text
remain product gaps. Header roles preserve the intended task allocation;
local seeded/custom grants can be wider than the operational-role document.
Physical printing/component work, destructive catalogue branches and an
unfamiliar-reader/A4 paper trial are unperformed. Artifact checks and editorial
read-back do not establish reader performance or exact acceptance.

The [batch review](remaining-guides-2026-10-20.md) records shared reconciliation,
actual UI trials, unperformed routes and final preservation/check results.
