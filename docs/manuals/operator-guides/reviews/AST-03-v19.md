# AST-03 v19 - Complete Task Pilot

Date: 2026-11-04. Status: Working draft; not accepted.

## Brief Established Before Composition

Reader: a Supervisor with a physical device and its manufacturer label, logged
in at Dashboard, who knows the physical work but has no assumed Snipe-IT
expertise. Outcome: the device has one matching registration and a safely
placed QR label that opens that registration.

Authority: current owner feedback, authoring-method.md, system.md,
components.md, layouts.md, screenshots.md and AST-03's operating boundaries.
The accepted v15 is the design reference; v18 is comparison evidence, including
the specifically rejected omission of the Dashboard creation tile. A new
specification cannot remove that requirement by substituting an abstract
equivalent function.

Required updates/corrections: illustrate duplicate search and retain both
Apparaten and Nieuwe Asset / Nieuwe aanmaken on Dashboard. Explain when to
create, retain the list plus as an alternative entry, keep registration notes
optional and show the actual Save action. Keep printer, template and loaded
size checks before printing. Maintain one continuous task, steps 1-8 over two
A4 sides, with completion only after verification.

Chosen improvements: give navigation a larger contextual Dashboard crop;
restore the opened-record check visually; connect captions to their controls;
use available room for recognition instead of retaining empty image frames.
These improvements must not shrink the useful identity/model fields or the
physical placement example compared with v18.

## Concrete Reader Walkthrough

1. On Dashboard recognize Apparaten and Nieuwe Asset together. Open Apparaten,
   search the physical S/N (or an existing tag) in the list's search field and
   wait for the results. Compare actual identity, not just the count. For a
   match, open that record and continue at step 5. The implemented instruction
   names its clickable asset tag, verified in AssetPresenter, instead of relying
   on an optional asset name. For no matching record,
   create using the list plus, or return with the browser Back action to
   Dashboard and choose Nieuwe Asset / Nieuwe aanmaken. Search is required
   before either creation entry; the creation buttons are alternatives.
2. In the create form keep the proposed asset tag and copy physical S/N.
   Distinguish internal tag from manufacturer serial. Unlock changes the tag;
   Aa preserves intentional case. Neither is a routine extra step.
3. Choose category and exact model/manufacturer code, including a suffix such
   as #ABH. HP Product ID/P/N identifies the model type, not the unique serial.
   A missing exact type uses CAT-01 and returns to this step.
4. Choose current work status (Being Processed in the example). Both new-entry
   note fields are optional. Check details and click the actual Opslaan control
   once. A duplicate response returns to comparison, not another submission.
5. Compare saved tag, serial, model and status. Use Asset openen in the saved
   result. A record already opened from search gets the same identity check.
6. Scroll to the QR-label panel. Compare its preview with the asset identity;
   select the appropriate template, loaded paper size and printer, then print
   once. Quick print in the result panel uses defaults. Failure concerns the
   same saved asset; do not create a replacement registration.
7. Use the whole underside photograph to orient the device with the front
   edge facing the reader. Put the label at lower right on a flat area clear
   of vents, ports, screws and service labels. The photograph is a separate
   placement example, not physical proof for the synthetic UI asset.
8. Scan and compare the opened tag, serial and model with the physical device.
   A damaged label permits manual tag/S/N lookup. A different identity means
   change nothing and ask Supervisor. Completion follows this check.

Concrete changes and costs against the external comparison basis:

- Step1 now keeps both full Dashboard tiles at 81 mm total width, with an
  instruction to use Apparaten first. The native highlighted search toolbar
  stays 130 mm wide. Its plus remains an alternative to the named tile after
  checking for a matching record. Browser Back supplies the return route.
  This makes the opening step taller; later fields are not shrunk to pay for it.
- Tag/serial and category/model crops increase from 79 to 84 mm; underlying
  pixels are unchanged. Unlock/Aa and HP's Product ID/P/N distinction remain.
  The suffix wording means the device's own part after #, not a universal #ABH.
- The CAT-01 handoff moves from the bottom reference strip to the missing-model
  instruction itself, retaining its full name and return to step3. The separate
  SC-01 reference is at the scan/manual-search step; HELP-01 and AST-02 remain
  relevant references on side2. The page1 bottom strip becomes a direct
  continuation rather than declaring completion or filling the former boxes.
- Both note fields are explicitly optional. Native Save remains 28 mm wide and
  its location above the form is named. Duplicate-message recovery remains with
  Save as well as the initial duplicate check.
- The saved row remains 177 mm wide, full print controls 80 mm, preview 27 mm
  and full physical photograph 80 mm. A status check names its location below
  the QR panel. Quick printing is explained as using defaults, not a second
  mandatory print action. No blind retry is taught for an uncertain outcome.
- The final visual now shows actual opened-record tag/S/N fields at 73 mm wide.
  The accepted title-only picture's model-location support is carried by the
  explicit instruction to compare the model above; no miniature duplicate of

- The search field's redundant red outline is removed because native yellow
  highlighting and its isolated toolbar already identify it. Focus remains
  only on the small plus, Asset openen and physical QR. Full form groups remain
  unoutlined. Calm conditional recovery is retained without STOP banners.
