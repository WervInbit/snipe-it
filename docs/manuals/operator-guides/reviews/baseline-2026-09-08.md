## Compare Or Reject A Later Proposal

1. Open the frozen latest version and the new candidate side by side. When
   an accepted predecessor also exists, compare that separately: intervening
   drafts have not inherited its acceptance.
2. Read the candidate review record for changed pages/steps, rationale,
   benefits, drawbacks, evidence, and remaining user-test questions.
3. Record accept, reject, or revise for that exact candidate and checksum.
   Rejection leaves the prior accepted version and checkpoint intact.
4. To recover a PDF, copy its checkpoint bytes into a separate review or
   recovery directory and verify SHA-256 against the manifest. Do not
   overwrite a different PDF using its old version number.
5. For source recovery, extract the ZIP into a separate empty directory.
   Compare only the affected source files before selectively restoring
   changes; shared generator files may also serve other proposals.
6. If an active manifest/registry selection must be rolled back, record the
   selected exact version and update those references together. Retain the
   rejected candidate and review outcome for traceability.

Do not extract the archive over the active repository or reset the whole
working tree to undo a guide proposal. Dependencies and application data
are outside this checkpoint.
