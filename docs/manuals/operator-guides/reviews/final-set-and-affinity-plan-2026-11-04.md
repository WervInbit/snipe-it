## Affinity Investigation And Recommended Route

Read-only Windows package inventory found `Canva.Affinity` version
`3.2.2.4557`. The native deliverable should therefore target `.af` for this
installation, rather than assuming an older Publisher `.afpub` target.
No Affinity app was launched, no document opened/imported and no settings
changed during this investigation.

Affinity documents [IDML import with page structure, text frames and basic
styles preserved](https://www.affinity.studio/page-layout-software).
Advanced formatting may need adjustment. Structured IDML followed by native
save/verification is the recommended initial route. The existing SVGs supply
useful source geometry, but importing an SVG or PDF alone does not demonstrate
clean paragraph frames, styles, picture frames and page masters.

The public [Affinity SDK DocumentApi](https://sdk.affinity.studio/33001/js/apis/DocumentApi/index.html)
also exposes document creation, export, saving and packaging. The inspected
reference is version `33001`, not proof that the installed 3.2.2 supports every
required operation. Native scripting remains an alternative to assess during
the proof, rather than an assumed complete automation path. No new connector,
script runtime or application upgrade is needed merely to write this plan.

## Native Editing Requirements

- Text is live, selectable paragraph text in sensible frames, with reusable
  styles for title, purpose, step, body, caption, help and footer. Avoid one
  object per glyph or hard-broken line when a paragraph should reflow.
- Screenshots use the full-resolution uncropped source in an editable picture
  frame with the intended crop/position. Supplying only the final cropped PNG
  would prevent later recovery of useful surrounding context. Include original
  captures and the physical photograph in the asset package.
- Focus marks, badges, borders, reference chips and diagram shapes/connectors
  remain separately editable native vector objects. Group each image and its
  annotations for moving/resizing while allowing independent adjustments.
  Recropping/replacing an image requires checking its focus alignment; automatic
  target tracking is not promised.
- Use named page/step groups and master elements for repeated structure.
  Diagram text and connectors must remain editable; a flattened diagram is not
  the intended handoff. Keep ordinary guide-specific composition flexible.
- Screenshots remain raster evidence: their UI text is not a native text layer.
  The recipient can replace/reframe the screenshot and edit all guide copy and
  annotations around it.
- Text-frame reflow does not imply the entire page automatically rearranges
  itself. The handoff must support straightforward manual layout adjustment.

The proof must demonstrate editing a paragraph, changing a style, replacing
and recropping an image using retained full source pixels, editing a focus
shape and diagram connector, saving/closing/reopening, and exporting matching
A4 pages. Inspect font substitution, text overflow, clipping, crop/focus
alignment, group usability and relocated-package resource resolution.

## Deliverables And Ownership

- One current PDF per guide, exported from its delivered native master.
- One `.af` per guide, organized for local editing, plus a shared template and
  documented styles. Separate files let an editor adjust one guide without
  handling the whole catalogue chapter set.
- A portable asset/source package with original screenshots/photos, editable
  diagram sources, font/style inventory, source/crop provenance and version
  ledger. Verify a relocated copy using embedded resources or proper packaged
  links, rather than relying on this workstation's absolute paths.
- One review index with all 25 guides, old/new links and a central list of
  meaningful additions, removals, moves, substitutions and unresolved issues.
- A short editing/export handoff. After delivery, the native Affinity files
  are the masters for manual text/layout changes and subsequent PDF export.
  Retained generation/IDML sources are versioned inputs; do not regenerate over
  a human-edited master without reconciling those changes first.

Acceptance requires complete relevant information and practical editing, not
only files that open. Application contradictions, unreadable targets, missing
controls, lost recovery, flattened guide text, broken fonts or resources, and
divergent PDF/native copies prevent that claim. A simulated editorial walkthrough
must not be reported as an observed novice-reader or physical print/scan trial.
