## Changes And Tradeoffs

| Change | Expected benefit | Drawback or review question |
| --- | --- | --- |
| Steps 1-2 inspect existing workflows before using the start action (AUD-07). | Reduces the chance of creating another run before noticing the continue route. | Adds a check to every start. This changes the previously accepted primary-route emphasis and needs an explicit review decision. |
| Step 3 has mutually exclusive A/B routes and both lead to step 4 (AUD-16). | Makes the branch and return point explicit. | Users must identify a suitable unfinished workflow; ambiguous, completed or multiple matching rows still need supervisor help. |
| Step 4 permits existing results when resuming. | Avoids telling users that every opened run must look neutral. | The screenshot illustrates a neutral card only; it is not a second resumed-state capture. |
| Larger instruction copy, full shared guide references, shared family color and a mixed asymmetric layout (AUD-11/17). | Gives instructions more readable space while retaining one page. | Fewer screenshots: the start button is named explicitly but has no dedicated crop. Test whether novices can locate it reliably. |

The typography and layout are opt-in pilot choices, not new global defaults.
The screenshot crops preserve the existing application imagery; the current
production UI has not been recaptured in this session. The visible example
profile must not become an instruction to use that profile for every device.
