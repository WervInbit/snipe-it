## Reader Outcome

The physical component is installed and its existing tracked identity is linked to the intended asset.

## Action And Choice Structure

- Open Components and Add / Install Component.
- Select the same existing tray/storage identity.
- Place physically, then Install once.
- Verify Tracked, tag, serial, link and the displayed asset specification.

## Operating Contract And Boundaries

- A shared name does not establish physical identity. Compare source, name, tag and serial where available before installation.
- An already registered component uses this route, not another CMP-02 registration.
- Unexpected identity or a condition barrier is handed to Supervisor before continuing.
- A real installed record can remain Extra alongside an Assumed baseline. Do not claim that installation always replaces that expectation automatically.
- One small unlabeled Components tab earns measured focus; the selected record and complete result do not need rings.
- For replacement, check that the old component has already been unlinked from this asset before Install/Create; unresolved removal/expectation goes to Supervisor. This is not an automatic baseline replacement action.

## Revision Reasoning

Required alignment: Current component controls and real Extra/Tracked outcome replace the older assumption of automatic baseline substitution.

Chosen improvement: Check physical identity before Install and the resulting specification before completion.

Preserve: Four actions, existing-record reuse, tray/source recognition and tag/serial result verification.

Placement and tradeoff: No catalogue calculation lesson or new registration handoff simply because a search is unresolved; Supervisor resolves that uncertainty.
