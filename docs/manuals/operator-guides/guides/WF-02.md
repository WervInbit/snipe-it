## Purpose

Work through the active workflow item by item, record truthful results, add required notes or image evidence, and recognize the saved completion state.

## Steps

1. `Controleer apparaat en run` - match asset tag/model in the real breadcrumb
   to the physical device; use the run chosen through its profile row in WF-01.
   The breadcrumb itself does not identify the profile.
2. `Lees de instructie` - use Show instructions / Toon instructies and read the
   complete real instruction before recording a result.
3. `Voer uit en kies resultaat` - record Pass/Fail or Done/Not Done truthfully.
   Optional items do not hold progression; required answers and required
   positive outcomes are different conditions.
4. `Voeg een notitie toe` - enter relevant findings in Note / Notitie, then
   check that Saved at has updated after typing. An old displayed timestamp
   does not prove a new save.
5. `Voeg foto of schermbeeld toe` - use Photo / Add photo, check the returned
   thumbnail, and exclude passwords/recovery codes/customer credentials.
6. `Controleer en kies Klaar` - answer required cards and wait for pending saves.
   Done / Klaar returns to the same asset's Workflows tab. Read the resulting
   profile state and guard explanation; completion is not sale release or
   proof that a prerequisite succeeded. Failed outcomes remain failed.

## Stop

Do not mark a result without performing the check. Stop and ask when the instruction, expected result, or physical device is unclear.

## Evidence Note

The live in-app `Foto` panel and `Foto toevoegen` action are sufficient for the V1 internal review candidate. The device-native camera/file picker is not shown because it varies by device and is outside this guide's required evidence scope.

Version 10 uses current blank-run captures so `Geslaagd` and `Mislukt` remain neutral before step 3. Instruction, note, and photo views keep the complete card visible. Step 1 uses `Valideer de actieve workflow` and shows a complete, readable breadcrumb context. In 4A, the application's yellow outline identifies `Notitie` as active while the red target identifies the note-entry field; this matches 5A, where the active `Foto` section and `Foto toevoegen` action have separate visual roles. Other action targets use measured source-pixel control bounds, and non-critical stop text is left to the help section instead of repeated beside the steps. The front-page `Klaar als` handoff says `Ga verder op de volgende pagina.`

## Complete When

Required answers and relevant evidence are saved, the user has returned to the
same asset, and the next permitted task or handoff is understood. A failed
required item can be answered but still block dependent work. Editing a
completed run is allowed; historical edits do not make an older run current.
